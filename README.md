# Two-Stage Detector: «Очки / Без очков»

Двухэтапный видеодетектор реального времени: **Haar-каскад (OpenCV, C++)** находит лицо в видеопотоке, а **самостоятельно обученная свёрточная нейросеть (PyTorch → ONNX)** классифицирует вырезанное лицо — *в очках* или *без очков*.

Итоговое практическое задание по дисциплине «3231.МЛН.F.26О Machine Learning», уровень «3» (3 балла), **Вариант А** — контроль состояния лица.

## Суть проекта

Подавать в CNN весь кадр (например, 1280×720) дорого и бессмысленно: сеть должна «смотреть» только на лицо. Поэтому задача решается в два этапа:

1. **Этап 1 — быстрый классический алгоритм.** Haar-каскад `haarcascade_frontalface_default.xml` находит лица на кадре. Ложные срабатывания отсекаются параметрами `minNeighbors=6`, `minSize=80×80` и выбором самого большого прямоугольника.
2. **Этап 2 — нейросеть.** Вырезанная область (ROI) приводится к тензору `1×3×96×96` и подаётся в CNN, экспортированную в ONNX. Класс определяется по максимуму вероятности.

Результат отрисовывается поверх кадра: рамка, название класса и уверенность в процентах (с контрастной чёрной обводкой текста).

## Техническое задание

**Стек:** Python (Google Colab, PyTorch, ONNX) + C++17 (OpenCV: `videoio`, `imgproc`, `objdetect`, `dnn`).

**Часть 1. Обучение и экспорт нейросети (Python / Colab)**

1. Датасет не менее 300 изображений на класс, разбиение 80% / 20% (train / val).
2. Аугментация: повороты ±15°, сдвиги до 10%, масштабирование, горизонтальное отражение, яркость/контраст.
3. Архитектура: не менее 3 свёрточных блоков с BatchNorm и пулингом, полносвязный классификатор с регуляризацией.
4. Accuracy на валидации ≥ 0.85, графики Loss и Accuracy по эпохам, экспорт в `.onnx`.

**Часть 2. Инференс видеопотока (C++ / OpenCV)**

1. Чтение видео с камеры или из файла; защита от выхода рамки за границы кадра.
2. ROI без лишнего копирования памяти; тензор с теми же разрешением, нормализацией и порядком каналов, что и при обучении.
3. Прямой проход ONNX-сети, выбор класса по максимуму, рамка и подпись с контрастной обводкой.
4. Клавиша `R` — включение/выключение сохранения ROI на диск с индикатором **REC**; `ESC` — выход.

**Ограничения:** работа в реальном времени, без утечек памяти и аварийных завершений (Segmentation fault / OpenCV Exception), когда лицо частично выходит за любой край кадра.


## Нейросеть

Реализована в PyTorch, обучается в Google Colab (`train_classifier.ipynb`).

**Вход:** `1×3×96×96`, RGB, значения `0..1` (без mean/std). **Выход:** вероятности (`Softmax` встроен в ONNX-граф).

| Слой | Параметры |
|------|-----------|
| Блок 1 | Conv2d(3→32, 3×3) → BatchNorm → ReLU → MaxPool(2) |
| Блок 2 | Conv2d(32→64, 3×3) → BatchNorm → ReLU → MaxPool(2) |
| Блок 3 | Conv2d(64→128, 3×3) → BatchNorm → ReLU → MaxPool(2) |
| Голова | AdaptiveAvgPool(1) → Flatten → Dropout(0.4) → Linear(128→64) → ReLU → Dropout(0.3) → Linear(64→2) |

**Обучение:** Adam (`lr=1e-3`, `weight_decay=1e-4`), CrossEntropyLoss, 25 эпох, batch size 32; сохраняется состояние с лучшей val accuracy.

**Аугментация (только на train):** `RandomRotation(15)`, `RandomAffine(translate=0.1, scale=0.9–1.1)`, `RandomHorizontalFlip`, `ColorJitter(brightness=0.3, contrast=0.3)`.

**Регуляризация:** BatchNorm, Dropout (0.4 и 0.3), weight decay, аугментация.

**Результаты:** Accuracy на валидации — `XX.X%` (требование ТЗ ≥ 85%). Графики Loss/Accuracy смотрите в выводе ноутбука `train_classifier.ipynb`.

## Защита границ кадра

Прямоугольник лица, найденный каскадом, может частично выходить за кадр. Чтобы избежать `cv::Exception` и Segmentation fault, рамка пересекается с границами матрицы:

```cpp
cv::Rect safe = best & cv::Rect(0, 0, frame.cols, frame.rows);
if (safe.width >= 20 && safe.height >= 20) {
    cv::Mat roi = frame(safe);   // подматрица — без копирования пикселей
    ...
}
```

Оператор `&` для `cv::Rect` возвращает пересечение двух прямоугольников; слишком маленькие обрезки отбрасываются.

## Ответы на вопросы для защиты

**1. Почему не подавать в CNN весь кадр?**
Сложность свёрточной сети растёт с числом пикселей. Кадр 1280×720 — это ~920 тыс. пикселей против 9 216 (96×96) у ROI, то есть в ~100 раз меньше вычислений. Каскад работает быстро на CPU, а сеть запускается только на одном небольшом фрагменте — FPS растёт, а фон не мешает классификации.

**2. Копируются ли пиксели при взятии подматрицы?**
Нет. `frame(safe)` создаёт новый заголовок `cv::Mat`, указывающий на тот же буфер данных (счётчик ссылок увеличивается). Поэтому изменение пикселей в `roi` изменит и исходный `frame`. Для независимой копии нужен `roi.clone()`.

**3. Как реализована защита границ и когда программа упала бы без неё?**
Через пересечение `best & cv::Rect(0, 0, frame.cols, frame.rows)`. Без неё падение (`cv::Exception` на assertion в `Mat::operator()`) происходит, когда лицо частично выходит за левый, правый, верхний или нижний край кадра — например, пользователь сильно сдвинулся в сторону.

**4. Какая размерность и порядок осей у изображения в OpenCV и у входа ONNX?**
OpenCV хранит изображение как `H×W×C` в порядке каналов **BGR**, `uint8` (0..255). Сеть ожидает `N×C×H×W` (`1×3×96×96`), **RGB**, `float32` в диапазоне 0..1 — именно так обучалась модель (`ToTensor`). `blobFromImage` делает всё сразу: ресайз, `swapRB=true` (BGR→RGB), масштабирование `1/255` и перестановку осей в NCHW. Без этого сеть получила бы данные с другим распределением и точность резко упала бы.

**5. Как предотвращается переобучение?**
В ноутбуке: BatchNorm, Dropout(0.4) и Dropout(0.3), weight decay в Adam, блок аугментации `train_tf`. При обучении на кадрах одной комнаты без аугментации train loss быстро падает почти до нуля, а val loss останавливается и затем растёт — график показывает растущий разрыв между train и val (модель запоминает фон и условия съёмки).

## Возможные проблемы

- **Не открывается камера на macOS** — выдайте терминалу доступ к камере в «Системные настройки → Конфиденциальность и безопасность → Камера».
- **`Не удалось загрузить модель/каскад`** — запускайте из корня репозитория или передайте пути аргументами.
- **CMake не находит OpenCV** — укажите путь: `cmake .. -DOpenCV_DIR=/path/to/opencv/build`.
- **Каскад не видит лицо** — Haar-каскад работает только с фронтальными лицами при хорошем освещении.
